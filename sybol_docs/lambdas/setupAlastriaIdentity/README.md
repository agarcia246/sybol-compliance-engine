# createAlastriaIdentity — AWS Lambda

Registers the Alastria on-chain identity for the Blockchain Manager service. The function is
**self-contained**: it requires no imports from the rest of the monorepo and bundles all logic
(wallet management, vault access, contract interaction, DID generation) internally.

## Overview

```
Trigger (manual / EventBridge)
        │
        ▼
┌──────────────────────────────────────────────────────────┐
│  createAlastriaIdentity  (Node 18 Lambda, eu-west-1)     │
│                                                          │
│  1. Load / create wallets  ──► AWS Secrets Manager       │
│  2. Fetch signing keys     ──► AWS Secrets Manager       │
│  3. Extract public key     ──► openssl (bundled)         │
│  4. Register identity      ──► Ethereum / Alastria RPC   │
│  5. Store DID              ──► AWS Secrets Manager       │
└──────────────────────────────────────────────────────────┘
```

The function is **idempotent**: if the identity is already registered on-chain it returns
`200 { alreadyRegistered: true }` without making any state-changing transactions.

The execution role (`createAlastriaIdentity-role`) requires:

| Policy | Why |
|---|---|
| `AWSLambdaBasicExecutionRole` (managed) | Write logs to CloudWatch |
| Inline `SecretsManagerAccess` | Read and write secrets under the `alastria/*` prefix |

The inline policy grants the following actions on `arn:aws:secretsmanager:<region>:<account>:secret:alastria/*`:

```
secretsmanager:GetSecretValue
secretsmanager:CreateSecret
secretsmanager:PutSecretValue
secretsmanager:DescribeSecret
```

## AWS Secrets Manager — secret structure

The function reads and writes secrets using the path scheme below.
All secrets store JSON objects.

### Wallet secrets  (`WALLET_SECRET_PREFIX` + name)

Default prefix: `alastria/wallets/`

| Secret path | Content |
|---|---|
| `alastria/wallets/main` | `{ "address": "0x…", "encryptedWallet": "{ … }" }` |
| `alastria/wallets/adminKey` | same format |
| `alastria/wallets/firstIdKey` | same format |

Wallets are stored as [ethers.js encrypted JSON keystores](https://docs.ethers.io/v5/api/signer/#Wallet-encrypt).
The keystore password is a static string (`"password"`) — the actual security boundary is the IAM
policy restricting access to the secret, not the keystore password.

### Signing key (`SIGNER_KEY_SECRET_NAME`)

Default: `alastria/signerKey`

```json
{ "value": "<raw-hex-private-key-without-0x>" }
```

Used to deterministically derive the `main` wallet on first run.

### Default PEM key (`DEFAULT_KEY_SECRET_NAME`)

Default: `alastria/defaultKey`

```json
{ "privateKey": "-----BEGIN EC PRIVATE KEY-----\n…\n-----END EC PRIVATE KEY-----" }
```

The EC secp256k1 private key in PEM format. Its public key is registered in `AlastriaPublicKeyRegistry`.

### DID output (`DID_SECRET_NAME`)

Default: `alastria/did/<ETHEREUM_IDENTIFIER>`

Written by the function after successful registration:

```json
{
  "did": "did:ala:besu:redT:<proxy-address-without-0x>",
  "address": "0x<proxy-address>",
  "ethereumIdentifier": "redT"
}
```

## Environment Variables

### Contract address resolution

The Lambda bundles a `config.js` file (auto-generated by the deploy pipeline) that maps every
deployed contract type → network → alias → address:

```js
// config.js (excerpt)
const alastriaContractsMap = {
  "AlastriaIdentityManager": [{
    "address": "0xbd4a2c84edb97be5beff7cd341bd63567e73f8c9",
    "network": "redT",
    "alias":   "aimRedT"
  }],
  "AlastriaPublicKeyRegistry": [{ ... }],
  ...
};
```

Resolution order for a given contract:
1. If the matching env var (`AIM_CONTRACT_ADDRESS` / `APK_CONTRACT_ADDRESS`) is set and is **not** `REPLACE_ME`, that value wins.
2. Otherwise the Lambda looks up `alastriaContractsMap[typeName]` filtered by `network === ETHEREUM_IDENTIFIER` and `alias === AIM_ALIAS`.
3. Falls back to any entry with a matching network, then to the first entry in the array.

This means you typically **do not need to set address env vars at all** — just keep `config.js` up to date.

### Required — must be set before first invocation

| Variable | Example | Description |
|---|---|---|
| `ETHEREUM_RPC` | `https://rpc.alastria.io` | JSON-RPC endpoint of the Ethereum-compatible node |
| `ETHEREUM_CHAIN_ID` | `2020` | Numeric chain ID of the target network |
| `ETHEREUM_IDENTIFIER` | `redT` | Logical network identifier — used to match addresses in `config.js` and as key in Secrets Manager |
| `ALASTRIA_ADMIN_KEY` | `0x27f1…` | Private key of the Alastria admin wallet (hex with `0x` prefix). **Store in Secrets Manager and inject at deploy time — never commit this value.** |
| `ALASTRIA_FIRST_ID_KEY` | `0xe784…` | Private key of the Alastria firstId wallet (hex with `0x` prefix). Same security advice as above. |
| `ENTITY_NAME` | `My Company SL` | Legal name of the entity being registered |
| `ENTITY_CIF` | `B12345678` | Tax ID of the entity |
| `TRUSTFRAMEWORK` | `ala` | DID trust framework. Allowed: `ala`, `veia` |
| `TECHNOLOGY` | `besu` | Blockchain technology. Allowed: `besu`, `quor`, `fabric`, `geth` |
| `NETWORK_ID` | `redT` | Network identifier. Allowed: `veia`, `local`, `redT`, `redB` |

### Optional — have sensible defaults

| Variable | Default | Description |
|---|---|---|
| `ALASTRIA_V1` | `false` | Set to `"true"` for Alastria v1.5 networks (adds extra `bool _active` param to `addEntity` and uses `adminKey` as delegator instead of `firstIdKey`) |
| `CONFIRMATIONS` | `1` | Number of block confirmations to wait for after each transaction |
| `GAS_PRICE` | _(provider default)_ | Gas price in wei as a decimal string (e.g. `"1000000000"` for 1 Gwei). If empty, the provider's suggested gas price is used |
| `WALLET_SECRET_PREFIX` | `alastria/wallets/` | Secrets Manager path prefix for stored keystores |
| `SIGNER_KEY_SECRET_NAME` | `alastria/signerKey` | Full secret name for the raw signing key |
| `DEFAULT_KEY_SECRET_NAME` | `alastria/defaultKey` | Full secret name for the PEM public-key source |
| `DID_SECRET_NAME` | `alastria/did/<ETHEREUM_IDENTIFIER>` | Full secret name where the resulting DID is stored |
| `AIM_ALIAS` | `aimRedT` | Alias used to look up the `AlastriaIdentityManager` address in `config.js`. Only needed if you have multiple deployments on the same network. |
| `APK_ALIAS` | `apkrRedT` | Alias used to look up the `AlastriaPublicKeyRegistry` address in `config.js`. |
| `AIM_CONTRACT_ADDRESS` | _(from config.js)_ | Manual override for the `AlastriaIdentityManager` address. Skips `config.js` lookup when set. |
| `APK_CONTRACT_ADDRESS` | _(from config.js)_ | Manual override for the `AlastriaPublicKeyRegistry` address. Skips `config.js` lookup when set. |
| `ENTITY_URL_LOGO` | _(empty)_ | URL of the entity logo |
| `ENTITY_URL_CREATE_AID` | _(empty)_ | URL of the entity's create-AID endpoint |
| `ENTITY_URL_AOA` | _(empty)_ | URL of the entity's AoA document |
| `AWS_REGION` | `eu-west-1` | AWS region (automatically set by the Lambda runtime) |

## Deployment

### First-time deploy

```bash
# 1. Install production dependencies
cd lambdas/setupAlastriaIdentity
npm install --omit=dev

# 2. Bundle
zip -r /tmp/createAlastriaIdentity.zip .

# 3. Create IAM role  (already done — skip if role exists)
aws iam create-role \
  --role-name createAlastriaIdentity-role \
  --assume-role-policy-document file://iam-trust-policy.json \
  --region eu-west-1

aws iam attach-role-policy \
  --role-name createAlastriaIdentity-role \
  --policy-arn arn:aws:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole

# (attach SecretsManagerAccess inline policy as well)

# 4. Create the function
aws lambda create-function \
  --function-name createAlastriaIdentity \
  --runtime nodejs18.x \
  --role arn:aws:iam::<ACCOUNT_ID>:role/createAlastriaIdentity-role \
  --handler index.handler \
  --zip-file fileb:///tmp/createAlastriaIdentity.zip \
  --timeout 300 \
  --memory-size 512 \
  --region eu-west-1
```

### Updating code after changes

```bash
cd lambdas/setupAlastriaIdentity
npm install --omit=dev
zip -r /tmp/createAlastriaIdentity.zip .

aws lambda update-function-code \
  --function-name createAlastriaIdentity \
  --zip-file fileb:///tmp/createAlastriaIdentity.zip \
  --region eu-west-1
```

### Updating environment variables

```bash
aws lambda update-function-configuration \
  --function-name createAlastriaIdentity \
  --region eu-west-1 \
  --environment "Variables={
    ETHEREUM_RPC=https://rpc.alastria.io,
    ETHEREUM_CHAIN_ID=2020,
    ETHEREUM_IDENTIFIER=redT,
    AIM_CONTRACT_ADDRESS=0x...,
    ALASTRIA_ADMIN_KEY=0x...,
    ALASTRIA_FIRST_ID_KEY=0x...,
    ENTITY_NAME=My Company SL,
    ENTITY_CIF=B12345678,
    TRUSTFRAMEWORK=ala,
    TECHNOLOGY=besu,
    NETWORK_ID=redT,
    ALASTRIA_V1=false,
    CONFIRMATIONS=1,
    SIGNER_KEY_SECRET_NAME=alastria/signerKey,
    DEFAULT_KEY_SECRET_NAME=alastria/defaultKey
  }"
```

> **Tip**: For `ALASTRIA_ADMIN_KEY` and `ALASTRIA_FIRST_ID_KEY` prefer using a Lambda environment
> variable backed by **AWS Secrets Manager parameter store integration** or inject the values via
> your CI/CD pipeline from a secrets vault rather than embedding them in plain text.

## Invoking the function

The function can be triggered manually, via EventBridge Scheduler, or from another Lambda/Step
Function. **The event payload is not optional** — it carries parameters that take priority over
environment variables and some of which are required for every invocation.

### Event payload schema

```json
{
  "ENTITY_NAME":           "Mi Empresa S.L.",
  "ENTITY_CIF":            "B12345678",
  "ALASTRIA_V1":           false,
  "WALLET_SECRET_PREFIX":  "alastria/wallets/",
  "ENTITY_URL_LOGO":       "",
  "ENTITY_URL_CREATE_AID": "",
  "ENTITY_URL_AOA":        ""
}
```

| Field | Type | Required | Description |
|---|---|---|---|
| `ENTITY_NAME` | string | **Yes** | Legal name of the entity being registered |
| `ENTITY_CIF` | string | **Yes** | Tax ID of the entity |
| `ALASTRIA_V1` | boolean | **Yes** | `true` for Alastria v1.5 networks; `false` for v2.2+ |
| `WALLET_SECRET_PREFIX` | string | **Yes** | Secrets Manager path prefix for wallet keystores (e.g. `alastria/wallets/`) |
| `ENTITY_URL_LOGO` | string | No | URL of the entity logo |
| `ENTITY_URL_CREATE_AID` | string | No | URL of the entity's create-AID endpoint |
| `ENTITY_URL_AOA` | string | No | URL of the entity's AoA document |

> **Priority rule**: event fields take priority over the corresponding environment variables.
> Fields that do not appear in the table above (e.g. `ETHEREUM_RPC`, `ETHEREUM_CHAIN_ID`) can
> only be configured via environment variables and are not overridable from the event.

### Invoking from the AWS CLI

```bash
aws lambda invoke \
  --function-name createAlastriaIdentity \
  --region eu-west-1 \
  --payload '{
    "ENTITY_NAME":          "Mi Empresa S.L.",
    "ENTITY_CIF":           "B12345678",
    "ALASTRIA_V1":          false,
    "WALLET_SECRET_PREFIX": "alastria/wallets/"
  }' \
  --cli-binary-format raw-in-base64-out \
  /tmp/response.json && cat /tmp/response.json
```

### Invoking with the helper script

A convenience wrapper is included at `testLambda.sh`. It validates required params, builds the
JSON payload, invokes the Lambda, and pretty-prints the CloudWatch log tail alongside the response.

```bash
# Full invocation
./testLambda.sh \
  --entity-name  "Mi Empresa S.L." \
  --entity-cif   "B12345678" \
  --alastria-v1  false \
  --wallet-prefix "alastria/wallets/" \
  --url-logo      "https://example.com/logo.png"

# Dry-run: checks IAM permissions only, Lambda does not execute
./testLambda.sh --dry-run
```

Script options:

| Option | Maps to | Required |
|---|---|---|
| `--entity-name <value>` | `ENTITY_NAME` | Yes |
| `--entity-cif <value>` | `ENTITY_CIF` | Yes |
| `--alastria-v1 true\|false` | `ALASTRIA_V1` | Yes |
| `--wallet-prefix <value>` | `WALLET_SECRET_PREFIX` | Yes |
| `--url-logo <value>` | `ENTITY_URL_LOGO` | No |
| `--url-create-aid <value>` | `ENTITY_URL_CREATE_AID` | No |
| `--url-aoa <value>` | `ENTITY_URL_AOA` | No |
| `--region <value>` | AWS region | No (default: `eu-west-1`) |
| `--dry-run` | `DryRun` invocation type | No |

### Success response  (first registration)

```json
{
  "statusCode": 200,
  "body": "{\"message\":\"Identity successfully registered in Alastria\",\"alreadyRegistered\":false,\"did\":\"did:ala:besu:redT:<proxy-address>\"}"
}
```

### Success response  (already registered)

```json
{
  "statusCode": 200,
  "body": "{\"message\":\"Identity already registered in Alastria\",\"alreadyRegistered\":true,\"did\":null}"
}
```

### Error response

```json
{
  "statusCode": 500,
  "body": "{\"message\":\"Identity setup failed\",\"error\":\"<error message>\"}"
}
```
